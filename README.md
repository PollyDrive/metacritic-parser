# Metacritic Game Tracker

**Metacritic Game Tracker** — это веб-сервис для автоматического сбора, анализа и мониторинга видеоигр с Metacritic. Приложение не только агрегирует оценки, но и с помощью LLM (ИИ) составляет выжимки (summaries) из отзывов критиков и игроков, а также находит геймплейные видео на YouTube и генерирует по ним краткие итоги.

---

## 🧭 Страницы интерфейса (UI)

### 1. Каталог (Home Page)
Главная страница с полным списком собранных игр.
- Включает **поиск** по названию и **фильтры** (по платформе, минимальному рейтингу, жанру и наличию мультиплеера).
- Отображает обложки игр, бейджи платформ и текущие оценки (Critic / User Score).

### 2. Карточка игры (Game Details)
Детальная страница конкретной игры (`/game/<slug>`).
- Выводит базовую информацию (жанры, разработчик, дата выхода).
- **AI Reviews**: Сгенерированные ИИ выжимки мнений критиков и обычных игроков.
- **YouTube Playthrough**: Краткий итог геймплейного видео (takeaway), сгенерированный ИИ на основе транскрипта с YouTube.
- **Similar Games**: Блок рекомендаций похожих игр (подбираются по пересечению жанров и близости Metascore).

### 3. Настройки (Settings)
Доступна по адресу `/monitoring/config` (требует авторизации оператора).
- Позволяет управлять поведением приложения "на лету" без перезагрузки сервера.
- Можно включить/выключить обогащение через YouTube, настроить лимиты (квоты API), а также изменить параметры ретраев (количество попыток и базовый интервал).

### 4. Мониторинг пайплайнов (Monitoring Dashboard)
Панель управления фоновыми задачами (`/monitoring`). Разделена на вкладки:
- **Pipeline Status**: Лайв-виджеты трех основных пайплайнов (`ingest`, `review_refresh`, `playthrough`). Позволяет запустить любой из них вручную.
- **Run History**: Таблица истории запусков. При клике на конкретный запуск открывается страница **Run Details** с детализацией (какие именно игры были обработаны).
- **Activity Feed**: Хронологическая лента событий, сгруппированная по играм (показывает историю действий над каждым конкретным тайтлом, например, новые отзывы или сгенерированные видео).
- **Errors Log**: Единый журнал ошибок парсинга, сетевых сбоев и таймаутов LLM.

## ⚙️ Допущения и логика работы (Под капотом)

Вся тяжелая работа вынесена в фоновые пайплайны (воркеры). Существует 3 независимых процесса:

### 1. Ingest (Сбор новых игр)
Запускается по расписанию (обычно раз в час):
- **Первый запуск за день**: Собирает данные из раздела "New Releases".
- **Последующие запуски**: Идут по общей пагинации каталога Metacritic ("See All"), запоминая страницу, на которой остановились.

### 2. Review Refresh (Обновление отзывов и затухание)
Запускается по своему расписанию (по умолчанию раз в 3 часа, `review_refresh.interval_hours` в Settings) — независимо от часового тика Ingest, т.к. Decayed TTL всё равно не даёт отзывам стать due чаще, чем раз в 3-7 дней.

Отзывы генерируются через LLM. Чтобы не тратить токены впустую, применяется **Decayed TTL** (период затухания) в зависимости от возраста игры, строго по `release_date` (без подстановки даты добавления в каталог, если релиз неизвестен):
- Игра вышла **меньше 7 дней назад**: отзывы обновляются раз в 3 дня.
- Игра вышла **от 7 до 28 дней назад**: отзывы обновляются раз в 7 дней.
- Игра старше **28 дней** (или дата релиза неизвестна): отзывы больше автоматически не обновляются.

Глубина выборки (`reviews.critic_sample_size` / `reviews.user_sample_size`) ограничена **10 отзывами** — ровно столько Metacritic отдаёт в SSR-пейлоаде своей страницы отзывов на один запрос, `?page=N` игнорируется сайтом. Значение выше 10 физически недостижимо.

### 3. Playthrough (YouTube выжимки)
Запускается по своему расписанию (по умолчанию раз в 3 часа, `playthrough.interval_hours` в Settings) — независимо от часового тика Ingest, т.к. суточный бюджет YouTube обычно тратится за один прогон после сброса, и последующие часовые тики просто находили нечего делать.

Ограниченный пайплайн для поиска геймплея на YouTube:
- Использует YouTube API для поиска видео и получения транскрипта.
- Управляется строгим суточным бюджетом (квотой), настраиваемым в Settings, чтобы не превысить лимиты API.

### Ретраи и обработка ошибок (Backfill)
- Если во время первичного парсинга (Ingest) отваливается LLM или ломается сеть, игра всё равно сохраняется в базу, а генерация текстов откладывается в очередь (deferred).
- **Exponential Backoff**: Отложенные задачи пытается выполнить пайплайн `Backfill`. Интервал между попытками увеличивается экспоненциально.
- Если задача исчерпала лимит попыток (по умолчанию 3), она помечается как `abandoned` и падает в **Errors Log** (Pipeline Reject).
- В системе работает **Global Lock**: нельзя запустить пайплайн вручную, если в этот момент работает другой воркер.
